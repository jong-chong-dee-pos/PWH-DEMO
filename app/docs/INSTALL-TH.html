คู่มือติดตั้ง PWH บน intranet

ระบบจัดการคลัง Part (PWH) สำหรับฝ่าย IT ระยะที่ 1: เปิดใช้งานบนเว็บเซิร์ฟเวอร์ภายในบริษัท

ดูเลขเวอร์ชันได้ในไฟล์ version.txt ในชุดติดตั้ง

  1. ภาพรวม
  2. สิ่งที่ต้องเตรียม
  3. ไฟล์ในชุดติดตั้ง
  4. ติดตั้งบน IIS (Windows Server)
  5. ติดตั้งบน Nginx (Linux)
  6. ติดตั้งบน Apache
  7. ตรวจหลังติดตั้ง
  8. ข้อมูลและการสำรองข้อมูล
  9. ย้ายข้อมูลจากลิงก์ claude.ai
  10. อัปเดตเวอร์ชัน
  11. ความปลอดภัย
  12. ปัญหาที่พบบ่อย

1. ภาพรวม

PWH เป็นเว็บแอปแบบไฟล์ล้วน (HTML, CSS, JavaScript) ไม่มีโปรแกรมฝั่งเซิร์ฟเวอร์ และไม่ต้องใช้ฐานข้อมูลในระยะที่ 1 เซิร์ฟเวอร์ทำหน้าที่ส่งไฟล์ให้เบราว์เซอร์เท่านั้น

  • ไม่ต้องใช้อินเทอร์เน็ต ฟอนต์และไลบรารีอ่าน Excel อยู่ในชุดติดตั้งครบ แอปไม่เรียกใช้เว็บภายนอกเลย และการตั้งค่าเซิร์ฟเวอร์ที่แนบมามีนโยบาย Content-Security-Policy ที่สั่งให้เบราว์เซอร์บล็อกการเชื่อมต่อออกนอกเซิร์ฟเวอร์ทุกชนิด
  • ข้อมูลเก็บในเบราว์เซอร์ของแต่ละเครื่อง (IndexedDB) ไฟล์ Excel ที่อัปโหลด กติกา และบัญชีผู้ใช้ จะไม่ถูกส่งไปที่เซิร์ฟเวอร์ ดูรายละเอียดในหัวข้อ 8
  • เบราว์เซอร์ที่รองรับ Microsoft Edge หรือ Google Chrome เวอร์ชันปัจจุบัน

2. สิ่งที่ต้องเตรียม

รายการรายละเอียด
เว็บเซิร์ฟเวอร์เลือกได้หนึ่งอย่าง: IIS 10 ขึ้นไป, Nginx หรือ Apache 2.4 พื้นที่ดิสก์ประมาณ 5 MB
ชื่อเว็บภายในเช่น pwh.company.local ชี้มาที่ IP ของเซิร์ฟเวอร์ใน DNS ภายใน
ใบรับรอง HTTPS ภายใน (แนะนำ)ออกจาก CA ภายในของบริษัท เครื่องลูกข่ายต้องเชื่อถือ CA นี้ ถ้ายังไม่มี เปิดแบบ http ได้ แต่แนะนำให้เปลี่ยนเป็น HTTPS เมื่อพร้อม ดูหัวข้อ 11
เครื่องผู้ใช้Edge หรือ Chrome ที่ไม่ได้ปิดการเก็บข้อมูลเว็บไซต์ (IndexedDB) ด้วย Group Policy และไม่ได้ตั้งให้ลบข้อมูลเว็บไซต์ทุกครั้งที่ปิดเบราว์เซอร์

3. ไฟล์ในชุดติดตั้ง

ไฟล์ / โฟลเดอร์ใช้ทำอะไร
index.html, css/, js/, vendor/, fonts/ตัวแอป วางทั้งหมดไว้ในโฟลเดอร์เดียวกันตามโครงสร้างเดิม
web.configการตั้งค่าสำหรับ IIS (ชนิดไฟล์ฟอนต์, header ความปลอดภัย, การแคช)
.htaccessการตั้งค่าแบบเดียวกันสำหรับ Apache
_server/nginx-pwh.confตัวอย่างการตั้งค่า Nginx
_server/csp.txtนโยบาย Content-Security-Policy ฉบับเต็ม เผื่อต้องตั้งในอุปกรณ์อื่น เช่น reverse proxy
version.txtเลขเวอร์ชันและวันเวลาที่สร้างชุดติดตั้ง
fonts/LICENSE-*.txtสัญญาอนุญาตฟอนต์ Anuphan และ IBM Plex Mono (SIL Open Font License 1.1 ใช้ในองค์กรได้)
ไฟล์ web.config, .htaccess และโฟลเดอร์ _server ไม่ใช่ส่วนของแอป ถ้าไม่ได้ใช้เซิร์ฟเวอร์ชนิดนั้น จะลบทิ้งก็ได้

4. ติดตั้งบน IIS (Windows Server)

  1. เปิด Server Manager แล้วเพิ่ม Role Web Server (IIS) ใช้แค่ Static Content กับ Default Document ก็พอ
  2. แตกไฟล์ zip แล้วคัดลอกเนื้อหาในโฟลเดอร์ pwh-intranet ไปไว้ที่ เช่น C:\inetpub\pwh
  3. เปิด IIS Manager แล้วเลือก Sites → Add Website
    • Site name: PWH
    • Physical path: C:\inetpub\pwh
    • Binding: https, port 443, Host name pwh.company.local แล้วเลือกใบรับรองภายใน (ถ้ายังไม่มี ใช้ http port 80 ไปก่อน)
  4. ไม่ต้องตั้งค่าอื่น ไฟล์ web.config ที่แนบมาตั้งชนิดไฟล์ .woff2, header ความปลอดภัย และการแคชให้แล้ว
  5. ให้สิทธิ์อ่านโฟลเดอร์แก่ IIS_IUSRS (ปกติมีอยู่แล้วเมื่อวางใน C:\inetpub)

5. ติดตั้งบน Nginx (Linux)

sudo mkdir -p /var/www/pwh
sudo unzip pwh-intranet-*.zip -d /tmp/pwh && sudo cp -r /tmp/pwh/pwh-intranet/* /var/www/pwh/
sudo cp /var/www/pwh/_server/nginx-pwh.conf /etc/nginx/conf.d/pwh.conf
# แก้ server_name, root และ path ของใบรับรองใน /etc/nginx/conf.d/pwh.conf
sudo nginx -t && sudo systemctl reload nginx

ถ้ายังไม่มีใบรับรอง ให้ลบบล็อก listen 443 ssl และบรรทัดที่ redirect ออก แล้วใช้ listen 80; แทน

6. ติดตั้งบน Apache

  1. คัดลอกไฟล์ทั้งหมดไปที่ DocumentRoot ของ virtual host เช่น /var/www/pwh โดยต้องมีไฟล์ .htaccess ไปด้วย
  2. เปิด module ที่ต้องใช้: sudo a2enmod headers
  3. ใน virtual host ตั้ง AllowOverride All (หรืออย่างน้อย FileInfo Indexes) ให้โฟลเดอร์นี้ แล้ว sudo systemctl reload apache2

7. ตรวจหลังติดตั้ง

  1. เปิด https://pwh.company.local/ ด้วย Edge หรือ Chrome ต้องเห็นหน้า ตั้งค่าครั้งแรก พร้อมภาพคลังที่มีพนักงานเคลื่อนไหว
  2. เปิด /version.txt ต้องเห็นเลขเวอร์ชันตรงกับชุดที่ติดตั้ง
  3. กด F12 เปิดแท็บ Network แล้วรีเฟรชหน้า ทุกรายการต้องมาจาก pwh.company.local เท่านั้น และแท็บ Console ต้องไม่มีข้อความสีแดงเรื่อง Content-Security-Policy
  4. ตัวอักษรภาษาไทยต้องเป็นฟอนต์ Anuphan ไม่ใช่ Tahoma ถ้าเป็น Tahoma ดูหัวข้อ 12
  5. สร้างบัญชีแอดมินคนแรก แล้วลองอัปโหลดไฟล์ Excel หนึ่งไฟล์ในโมดูล 1

8. ข้อมูลและการสำรองข้อมูล (สำคัญ)

ในระยะที่ 1 ข้อมูลไม่ได้อยู่บนเซิร์ฟเวอร์ เบราว์เซอร์แต่ละเครื่องเก็บข้อมูลของตัวเอง แยกตามชื่อเว็บที่เปิด
  • เครื่องแต่ละเครื่อง หรือผู้ใช้ Windows แต่ละคน มีข้อมูลและบัญชีผู้ใช้แยกกัน แอดมินต้องตั้งค่าในเครื่องที่ใช้งาน
  • ถ้าเปลี่ยนชื่อเว็บ พอร์ต หรือเปลี่ยนจาก http เป็น https เบราว์เซอร์จะมองว่าเป็นเว็บใหม่ และข้อมูลจะเริ่มจากว่าง ให้สำรองข้อมูลก่อนเปลี่ยน แล้วกู้คืนหลังเปลี่ยน ควรตัดสินใจชื่อเว็บและ https ให้เรียบร้อยก่อนเริ่มใช้งานจริง
  • การล้างข้อมูลเบราว์เซอร์ (Clear browsing data → Cookies and site data) จะลบข้อมูล PWH ในเครื่องนั้น
  • วิธีสำรอง: แอดมินเข้าเมนู ผู้ใช้ แล้วไปที่หัวข้อ สำรองและกู้คืนข้อมูล กด บันทึกไฟล์สำรอง จะได้ไฟล์ pwh-backup-ปีเดือนวัน-เวลา.json ที่รวมไฟล์ Excel ทั้งหมด การตั้งค่า กติกา สถานการณ์จำลอง และบัญชีผู้ใช้ ขนาดประมาณ 20–40 MB
  • แนะนำ: สำรองทุกสัปดาห์และทุกครั้งที่อัปโหลดข้อมูลชุดใหญ่ เก็บไฟล์ไว้ในไดรฟ์กลางของบริษัทที่จำกัดสิทธิ์ เพราะไฟล์สำรองมีข้อมูลการผลิตและบัญชีผู้ใช้ (รหัสพนักงานถูกเก็บแบบ hash ไม่ใช่ตัวเลขจริง)
  • วิธีกู้คืน: ในเครื่องที่มีบัญชีแล้ว ไปที่เมนู ผู้ใช้ → เลือกไฟล์สำรอง → กู้คืน → ยืนยันกู้คืน ในเครื่องใหม่ที่ยังไม่มีบัญชี ใช้ลิงก์ มีไฟล์สำรองข้อมูล? กู้คืนจากไฟล์ ใต้หน้าตั้งค่าครั้งแรก การกู้คืนจะแทนที่ข้อมูลทั้งหมดในเครื่องนั้น จากนั้นเข้าสู่ระบบด้วยบัญชีที่อยู่ในไฟล์สำรอง

9. ย้ายข้อมูลจากลิงก์ claude.ai

  1. เปิดลิงก์ PWH เดิมบน claude.ai แล้วเข้าสู่ระบบด้วยบัญชีแอดมิน
  2. ไปที่เมนู ผู้ใช้ → บันทึกไฟล์สำรอง แล้วกดยืนยันการบันทึกไฟล์ที่ claude.ai แสดง
  3. เปิด PWH บน intranet ในเครื่องที่จะใช้งาน ที่หน้าตั้งค่าครั้งแรก กด มีไฟล์สำรองข้อมูล? กู้คืนจากไฟล์ แล้วเลือกไฟล์ที่ได้
  4. เข้าสู่ระบบด้วยบัญชีเดิม ข้อมูล บัญชี และรหัสพนักงานใช้ได้เหมือนเดิม

10. อัปเดตเวอร์ชัน

  1. แนะนำให้แอดมินสำรองข้อมูลก่อน (หัวข้อ 8)
  2. แตกไฟล์ zip เวอร์ชันใหม่ แล้วคัดลอกทับไฟล์เดิมทั้งหมดในโฟลเดอร์ของเว็บ
  3. ผู้ใช้เปิดหน้าเว็บใหม่หรือกด F5 ข้อมูลในเบราว์เซอร์ยังอยู่ครบ การตั้งค่า Cache-Control: no-cache ทำให้เบราว์เซอร์ตรวจไฟล์ใหม่ทุกครั้ง จึงไม่ต้องล้างแคช

11. ความปลอดภัย

  • ไม่มีข้อมูลออกนอกเครือข่าย แอปไม่มีโค้ดส่งข้อมูลออก และ Content-Security-Policy (connect-src 'self', default-src 'self') สั่งให้เบราว์เซอร์บล็อกการเชื่อมต่อไปที่อื่นทั้งหมด
  • ระบบล็อกอินในระยะที่ 1 ใช้แบ่งหน้าที่ระหว่างแอดมินกับผู้ใช้งาน แต่ยังไม่ใช่การป้องกันระดับเซิร์ฟเวอร์ เพราะข้อมูลและบัญชีอยู่ในเบราว์เซอร์ ผู้ที่ใช้เครื่องมือนักพัฒนาของเบราว์เซอร์ได้ยังเข้าถึงข้อมูลในเครื่องนั้นได้ ระยะที่ 2 (ข้อมูลกลางบนเซิร์ฟเวอร์) จะแก้เรื่องนี้
  • HTTPS แนะนำให้ใช้ แม้เปิดแบบ http แอปก็ยังทำงานครบ รวมถึงการเข้ารหัสรหัสพนักงานด้วย SHA-256 แต่ HTTPS ป้องกันการดักอ่านในวง LAN และควรตั้งก่อนเริ่มใช้งานจริงตามเหตุผลในหัวข้อ 8
  • จำกัดการเข้าถึง ถ้าต้องการ จำกัดให้เปิดได้เฉพาะวง LAN หรือ VLAN ของคลังด้วยไฟร์วอลล์หรือการตั้งค่าเว็บเซิร์ฟเวอร์

12. ปัญหาที่พบบ่อย

อาการสาเหตุและวิธีแก้
หน้าเว็บว่างขาวไฟล์ใน js/ ไม่ครบ หรือเซิร์ฟเวอร์ส่งไฟล์ .js ด้วยชนิดผิด กด F12 ดูแท็บ Console แล้วคัดลอกไฟล์ใหม่ทั้งชุด
ภาษาไทยเป็นฟอนต์ Tahomaเซิร์ฟเวอร์ไม่รู้จักชนิดไฟล์ .woff2 บน IIS ตรวจว่ามีไฟล์ web.config อยู่ บน Nginx หรือ Apache ตรวจบรรทัด font/woff2
IIS แจ้ง error 500.19 หลังวาง web.configมีการตั้งชนิดไฟล์หรือ header เดียวกันไว้แล้วที่ระดับเซิร์ฟเวอร์ ลบบรรทัดที่ซ้ำออกจาก web.config
Console มีข้อความ Content-Security-Policy สีแดงอุปกรณ์อื่น เช่น proxy หรือ load balancer ตั้ง CSP ซ้อน ให้ใช้ค่าใน _server/csp.txt เพียงชุดเดียว
ข้อมูลหายหลังปิดเบราว์เซอร์นโยบายของเครื่องลบข้อมูลเว็บไซต์ตอนปิดเบราว์เซอร์ หรือเปิดในโหมดส่วนตัว (InPrivate หรือ Incognito) ให้ยกเว้นชื่อเว็บ PWH จากนโยบายนั้น แล้วกู้คืนจากไฟล์สำรอง
ข้อมูลว่างหลังเปลี่ยนชื่อเว็บหรือเปลี่ยนเป็น httpsเป็นพฤติกรรมปกติของเบราว์เซอร์ (หัวข้อ 8) ให้กู้คืนจากไฟล์สำรอง
บันทึกไฟล์สำรองแล้วไม่มีไฟล์ตรวจว่าเบราว์เซอร์อนุญาตการดาวน์โหลดจากเว็บนี้ และดูในโฟลเดอร์ Downloads

ระยะถัดไป

ระยะที่ 2 จะเพิ่มตัวบริการข้อมูลและฐานข้อมูลบนเซิร์ฟเวอร์เดียวกัน เพื่อให้ทุกเครื่องใช้ข้อมูลชุดเดียวกันและตรวจสิทธิ์ที่เซิร์ฟเวอร์ ข้อมูลที่ใช้ในระยะที่ 1 ย้ายเข้าได้ด้วยไฟล์สำรองข้อมูลชุดเดียวกันนี้
